# Runbook: исследование приёмника

Draft 0.1 · 2026-10-18. Ограниченный E00.5 выполнен на Apple TV 3/Sony; фактические команды, наблюдения и ограничения — в [отчёте](../testing/E00_5_2026-10-18.md). Остальные сценарии остаются планом.

## E00.5: первый вечер с готовыми утилитами

Цель — проверить исходную возможность воспроизведения на Apple TV 3 и Sony до написания приложения и принятия всего SPEC. Cast пока отсутствует по ответу владельца. План — до 60–90 минут; не превращать один неудачный сценарий в бесконечную настройку стенда.

1. Записать прошивки и режим доступа, включить нужный телевизор, выбрать умеренную громкость. Проверить версии доступных утилит. Стенд 2026-10-18: macOS 15.7.9, FFmpeg 9.0.1, установленный pyatv 0.18.0 и go2tv 2.7.0. Caddy не устанавливался и для выполненного smoke не понадобился. Перед повтором проверить версии и путь запуска.
2. Подготовить один законченный синтетический MP4: 720p/30, H.264 High level 4.0, AAC, 120 секунд, видимое время и checksum/probe. `drawtext` отсутствует в проверенной сборке FFmpeg; использовать встроенный `testsrc` с временной меткой либо выбрать сборку с drawtext. Исходный Homebrew FFmpeg GPL-enabled: он подходит для локального опыта, а состав дистрибутива приложения выбирается отдельно.
3. Apple TV: `atvremote --storage none scan`, затем выбрать именно RX-ATV3-01. Передать локальный файл через `play_url`: встроенный сервер pyatv выдаёт выбранный файл. Пример после заполнения локальных переменных: `atvremote --id "$ATV_ID" "play_url=$FIXTURE"`. Процесс оставить работающим до конца опыта. Если нужно сопряжение, выполнить штатный flow закреплённой версии; сохранить секрет вне отчёта. Discovery с `--storage none` не читает пользовательское хранилище; даже его вывод может содержать автоматически сформированные credentials — raw output не коммитить. [CLI](https://pyatv.dev/documentation/atvremote/), [local file](https://pyatv.dev/development/stream/).
4. Sony: `go2tv -l`, сопоставить description с KDL-48W605B; затем `go2tv -v "$FIXTURE" -t "$SONY_DESCRIPTION_URL"`. URL берётся из discovery, а не из предположения о порте. На первом проходе — без субтитров и transcoding. [go2tv CLI](https://github.com/alexballas/go2tv).
5. Для каждого устройства записать отдельно: start accepted; изображение; звук; pause/resume; seek вперёд/назад по метке времени; stop. Команды управления брать из `--help` закреплённой версии; пульт телевизора проверяет другой путь, чем команды утилиты, — записывать это различие. Если control недоступен, результат partial, а не провал всего playback.
6. Завершить созданные процессы и проверить освобождение сервера. Записать короткую строку результата по форме ниже. Неудача с конкретным сообщением и следующей проверкой — полезный результат этого smoke; она не закрывает аппаратную приёмку v1.

### Проверка HTTP при диагностике seek

`python -m http.server` не использовать как baseline сервера с Range. Если нужен отдельный сервер, Caddy запускается только из временного каталога с тестовым клипом, без directory listing: `caddy file-server --root "$FIXTURE_DIR" --listen "$LAN_BIND" --no-compress`. Его обычный file-server не добавляет сам по себе требуемый DLNA-профиль; для Sony первый путь — go2tv.

С другого разрешённого LAN-хоста проверить **GET**, а не только HEAD:

```sh
curl --max-time 10 --range 0-99 -D range.headers -o range.bin "$MEDIA_URL"
wc -c range.bin
```

Ожидание для файла длиннее 100 байт: 206, `Content-Range: bytes 0-99/…`, ровно 100 байт. HEAD может вернуть 200, игнорируя Range: `curl -I` не доказывает корректную частичную выдачу. Для custom server далее проверить 416 и revoke; это E02, не prerequisite написания собственного сервера ради E00.5. [Caddy](https://caddyserver.com/docs/command-line#caddy-file-server).

### Разрешения Mac

На macOS 15+ отдельно проверить Local Network у собранного приложения. Apple допускает автоматически CLI из Terminal/SSH; процесс из desktop-агента может иметь другую ответственную программу. Успех в Terminal не проверяет .app, отказ discovery не означает отсутствие устройства. Application Firewall проверять отдельно. [Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy).

### Apple TV 3: отдельное управление DMAP (pyatv 0.18.0)

`play_url` передаёт видео через AirPlay. `pause`, `play`, `set_position` и `stop` могут идти через DMAP. Отказ управления после успешного старта видео исследовать отдельно от media delivery. Сначала проверить доступность DMAP; pairing не запускать автоматически, если контроль уже работает.

При необходимости: `atvremote --storage-filename "$PAIRING_STORE" --id "$ATV_ID" --protocol dmap --remote-name OpenMediaCast-Lab --pin 4826 pair`. На приставке открыть меню пультов/Remote, выбрать OpenMediaCast-Lab, ввести указанный одноразовый для опыта PIN; после подтверждения владельцем завершить ожидание CLI клавишей Enter. В pyatv 0.18.0 именно DMAP показывает PIN для ввода на приставке; AirPlay pairing имеет другой flow. Путь PAIRING_STORE — приватный файл вне Git и вне каталога HTTP-раздачи, с ограниченными правами. CLI печатает credentials после pairing: не включать их в отчёт.

Первое окно держит `play_url` и встроенную раздачу; во втором использовать ту же конфигурацию и выбранный receiver: `atvremote --storage-filename "$PAIRING_STORE" --id "$ATV_ID" --protocol dmap pause`, затем `play`, `set_position=60`, `set_position=15`, `stop`. Позиции — абсолютные секунды; подтверждение по видимой метке на экране. Без отдельного pairing применять `--storage none` в обоих окнах. Не запускать два playback-процесса одновременно. Сверено с установленным CLI и pairing-кодом pyatv 0.18.0; [исходник версии](https://github.com/postlund/pyatv/blob/v0.18.0/pyatv/scripts/atvremote.py).

### Закреплённые инструменты и клип

Для E00.5 выбран pyatv 0.18.0 (`uv tool install pyatv==0.18.0`) и официальный macOS ARM64 release go2tv v2.7.0. Фактический запуск и ограничения записываются в отчёт опыта отдельно от скачивания/установки. FFmpeg 9.0.1 уже установлен. Обновление версий во время опыта — новая переменная, требующая записи.

Клип хранится в согласованном `fixtures-local/` внешней капсулы, исключённом из Git; descriptor — `session-artifacts/notes/2026-10-18-smoke-fixture.json` внешнего репозитория. Перенос сохраняет байты и SHA-256. При регенерации вычислить новую сумму; старую не переносить автоматически.

## Общая подготовка

Получить разрешённый target, модель/прошивку, режим доступа и тестовую LAN. Зафиксировать исходный snapshot инструмента, версию библиотеки и fixture. Начать с короткого synthetic MP4 H.264/AAC, а не личного фильма. Звук — умеренный; duration ограничен. Записать, где проходит поток: компьютер → локальный HTTP → приёмник.

Сначала убедиться, что сервер корректно отдаёт выбранный законченный файл, HEAD и диапазоны. URL должен содержать непрогнозируемый идентификатор сессии, не путь к файлу. Для отладки использовать псевдонимы устройств; реальные IP и pairing secrets не сохранять в публичном отчёте.

## AirPlay / Apple TV 3

Кандидат lab: pyatv. Зафиксировать точную версию и её актуальный API. Проверить обнаружение AirPlay-сервиса, device authentication/PIN и необходимость отдельного control protocol. Статический пароль и PIN-подтверждение не взаимозаменяемы. Если текущая настройка не поддерживается библиотекой — описать ограничение, не отключать защиту для скрытого обхода.

Тестировать последовательно load, наличие изображения и звука, pause, resume, seek +30 s, seek назад, stop. Сверять изменение времени на устройстве/в доступной телеметрии, а не только возврат Python-функции. Приёмник может не сообщить подробную ошибку — поэтому человеческое наблюдение является отдельным полем.

Источник: [pyatv stream API](https://pyatv.dev/development/stream/). Уже работающий системный mirroring — полезный baseline сети, но другой сценарий.

## Google Cast

Кандидаты: PyChromecast и Rust-клиент после первого baseline. Использовать физический video-capable Cast receiver, записать модель. Запустить Default Media Receiver и load локального URL. Проверить MIME, status events, seek и закрытие сессии. Chromecast должен видеть адрес компьютера; `localhost` в URL указывает на сам приёмник.

Отдельно проверить CORS для subtitles/HLS, если эти функции входят в spike. Интернет-зависимость загрузки receiver определить экспериментом, не отключая сеть домашним устройствам без согласования. Смартфон или mock не заменяет этот тест.

Источники: [PyChromecast](https://github.com/home-assistant-libs/pychromecast), [Cast media](https://developers.google.com/cast/docs/media).

## DLNA / Sony KDL-48W605B

Проверить Renderer в домашней сети телевизора и разрешение контроллера, используя его собственное меню. [Руководство модели](https://helpguide.sony.net/gbmig/C5551001/v1/eng/index_598_322.html) содержит соответствующие главы; точные названия меню уточняются на экземпляре владельца.

Первый baseline — go2tv; подробное исследование — async-upnp-client. Выполнить SSDP discovery, прочитать description, service types и доступные actions. Проверить DIDL-Lite/protocolInfo, contentFeatures.dlna.org, transferMode.dlna.org и фактический смысл OP/FLAGS. Начать с polling GetTransportInfo/GetPositionInfo; GENA callback вводить только при необходимости. Сетевые XML и callback URL недоверенные: ограничить размер, время и допустимые адреса в реализации. Найденные особенности записывать с firmware, fixture и evidence, а не обобщать на все Sony.

## Отчёт и остановка

Отчёт содержит ID теста, дату, OS, library version/commit, device/firmware, auth mode, fixture checksum/probe, transport, каждую команду и фактический результат, latency, ошибки и cleanup. Поля со значением unknown сохранять, не угадывать.

Остановить опыт при несанкционированном target, изменении требований безопасности, выдаче постороннего файла, неограниченном процессе/зависании. Базовый timeout одной попытки — предложение 30 s, затем штатная отмена; точное значение согласуется под тест. Запрещён бесконечный retry. Наблюдение успеха одного клипа не переносится на 4K, HEVC, все субтитры или другую прошивку.

## Особенности проверенных экземпляров: 2026-10-18

Apple TV 3/ATV SW 8.4.4: pyatv 0.18.0, выбранный экземпляр не потребовал дополнительного AirPlay/DMAP pairing; local MP4 и DMAP control подтверждены владельцем. Поле media type Music не соответствовало видимому видео. Это не отменяет pairing для других настроек/устройств.

Sony KDL-48W605B, firmware unknown: обычная LAN, не Wi-Fi Direct. go2tv 2.7.0 требует TTY и подходящий TERM; файл/пауза работают. REL_TIME seek подтверждён прямым SOAP при раздаче go2tv. Один вариант XML serialization получил HTTP 500, другой с локальным xmlns:u на action прошёл; причина не установлена. Сохранить оба варианта как кандидаты проверки будущего адаптера, не объявлять обязательный vendor workaround без изолированного опыта. [Доказательства и точный scope](../testing/E00_5_2026-10-18.md).
