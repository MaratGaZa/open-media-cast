# ADR-001: два репозитория, платформы как модули

Статус: **Accepted**. Решение владельца: 2026-10-18. Принятие этого ADR не принимает ADR-002 или продуктовый scope Draft SPEC.

## Контекст

Нужны отдельно учебные/сессионные материалы и код приложения. У платформ различаются UI, доступ к файлам, медиабэкенды и жизненный цикл. Требования к очереди, сессиям и протоколам при этом связаны.

## Рассмотренные варианты

| Вариант | Плюсы | Издержки |
|---|---|---|
| Капсула + единый source-репозиторий | Один PR может обновить core, контракты и клиентов; единые версии и тесты | Нужно дисциплинированное модульное деление и фильтры CI |
| Капсула + desktop/core + Android | Android можно выпускать независимо | Потребуется версионированный core-артефакт, проверка совместимости и координация изменений между репозиториями |
| Капсула + core + репозитории каждой ОС | Независимые команды, права доступа и циклы релизов | Много cross-repo PR, release orchestration и риск рассогласования; упаковка интерфейса ядра появляется раньше продукта |

Выбран первый вариант. Репозиторий — граница совместного изменения и истории; модуль — граница ответственности. Разные API ОС требуют адаптеров, но не требуют отдельных репозиториев.

## Решение

- Внешний Git root: `open-media-cast/`.
- Source Git root: `open-media-cast/project/`.
- Внешний `.gitignore` исключает `/project/`; submodule не вводится.
- Канонические SPEC/ADR/plans/runbooks/testing/rules и skills находятся в source-репозитории.
- Внешние research/learning/owner-guide/session-artifacts — отдельная история.
- Коммиты и PR каждого репозитория независимы; если изменение затрагивает оба, связывать их явными ссылками и SHA. Одного атомарного commit на два репозитория нет.
- Внешнюю капсулу нельзя считать полным backup кода: оба репозитория должны резервироваться отдельно.

## Критерий будущего разделения

Пересмотреть, когда есть независимая команда/права доступа, устойчивый версионированный контракт ядра, несколько потребителей и реальная потребность разных release cycles. До разделения создать contract tests и способ получения точной версии ядра. Обратное движение — сведение в monorepo с сохранением истории — отдельная миграция.

## Проверка

`git rev-parse --show-toplevel` из обоих корней возвращает разные ожидаемые пути. `git check-ignore project/README.md` во внешнем корне подтверждает исключение. Внешний `git ls-files` не содержит файлов приложения. Remote, initial commit и публикация не входят в принятие данного ADR автоматически.
