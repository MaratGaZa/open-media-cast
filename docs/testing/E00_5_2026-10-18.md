# E00.5 — опыт с готовыми утилитами, 2026-10-18

Статус: ограниченный E00.5 завершён для Apple TV 3 и Sony; результаты сторонних утилит и прямых DLNA-команд, не квалификация Open Media Cast. Код приложения отсутствует.

Baseline до опыта: source `b8ae469`, капсула `d7c38ba`. Изменение плана на небольшой MVP начато по предложению владельца во время опыта и остаётся отдельным Draft diff. Отчёт не требует принятия стека.

## Стенд и инструменты

- Mac mini M4, macOS 15.7.9 (24G830), ARM64; Python 3.13.11 ARM64, pyatv 0.18.0 через uv 0.12.13.
- go2tv 2.7.0, официальный macOS ARM64 archive; SHA-256 `18c6b4d7efcdcf46f2484ab0e50f3fac15795d119b2512a3470ad19af1c3e7a6`. Версия/help выполнены. CLI требует TTY. Отдельно скопированный binary завершался с 137; полный app bundle запускается. `codesign --verify` исходного bundle сообщил invalid signature; подпись и настройки macOS не изменялись. Для опыта сохранён полный bundle в пользовательском каталоге инструментов, команда — symlink на него. Это не доказательство готовности выпуска go2tv или нашего приложения.
- Fixture: 120 s, MP4 H.264 High L4.0, 720p30 yuv420p, AAC LC 48 kHz mono, временная метка; FFmpeg 9.0.1/VideoToolbox. SHA-256 `3b77da2edbf4289b076e7655bb2849e2906cdc9e7bfaf946c5ddde5418db9267`. Постоянная копия во внешнем ignored fixtures-local; личное медиа не использовалось.
- Только выбранная домашняя LAN; реальные адреса, device identifiers и credentials исключены из отчёта. Другие найденные устройства не использованы.

## RX-ATV3-01

Модель Apple TV 3; discovery сообщил ATV SW 8.4.4. Владелец выбрал нужную приставку и наблюдает экран. AirPlay pairing NotNeeded, DMAP Optional; отдельное pairing не выполнялось, хранилище credentials отключено `--storage none`. AirPlay `play_url` выдаёт выбранный локальный файл через встроенный HTTP pyatv; управление отдельным процессом `--protocol dmap`.

| Действие | Машинный результат | Наблюдение владельца |
|---|---|---|
| Start, попытка 1 | play_url завершился с 0; отдельный запрос DMAP показал Idle — этого недостаточно для вывода | Подтвердил видео, звук и управление физическим пультом |
| Pause, попытка 2 | Команда 0; Paused, 7/120 s | Подтвердил остановку картинки/таймера |
| Resume | Команда 0; Playing, 8/120 s | Подтвердил |
| Seek вперёд, абсолютные 60 s | Команда 0; Playing, 60/120 s | Подтвердил скачок по таймеру |
| Seek назад, абсолютные 15 s | Команда 0; Playing, 15/120 s | Подтвердил скачок назад |
| Повторная pause | Команда 0; Paused, 21/120 s | Подтвердил |
| Stop после ожидания, попытка 2 | Раздачу уже закрыл лимит времени процесса; последующий stop/Idle не доказывает активную остановку | Не засчитано |
| Stop при активном видео, попытка 3 | До команды Playing, 8/120 s; stop 0, затем Idle; play_url сам завершился с 0 | Владелец подтвердил выход из видео примерно через 10 секунд |

Во время попытки 2 pyatv помечал media type Music, хотя владелец видел тестовое видео. Не использовать это поле как самостоятельное доказательство типа контента. Все playback-процессы завершены, серверы принадлежали этим процессам. Попытка 2 принудительно ограничена по времени; попытка 3 завершилась штатно после stop. HTTP Range GET с другого LAN-хоста не проверялся, хотя видимая перемотка работала. Точную latency от отправки до кадра не измеряли.

## RX-SONY-01

Discovery go2tv обнаружил BRAVIA KDL-48W605B как DLNA. Description подтвердил Sony Corporation/KDL-48W605B и AVTransport:1, RenderingControl:1, ConnectionManager:1. Поле modelNumber: MINT1.7.0.1; не выдаём его за установленную firmware, она пока unknown. URL description/control/SCPD взяты из discovery и описания сервиса. Подключение — обычная домашняя LAN; Wi-Fi Direct не использовался.

| Действие | Машинный результат | Наблюдение владельца |
|---|---|---|
| Start через go2tv | UI Playing; позднее AVTransport PLAYING/OK, 6.400/120 s | Подтвердил видео и звук |
| Pause клавишей p go2tv | UI Paused | Подтвердил остановку таймера/картинки |
| Pause прямым SOAP, последний проход | HTTP 200; PAUSED_PLAYBACK/OK | Подтвердил |
| Resume прямым SOAP Play(Speed=1) | HTTP 200; позиция 9.933 s после ожидания | Подтвердил |
| Seek REL_TIME 00:01:00 | HTTP 200; спустя ~4 s позиция 64.433 s | Подтвердил скачок вперёд |
| Seek REL_TIME 00:00:15 | HTTP 200; спустя ~4 s позиция 18.700 s | Подтвердил возврат назад |
| Stop прямым SOAP | HTTP 200; STOPPED/OK | Подтвердил выход из видео |

Первый запуск CLI без TTY завершился локальной ошибкой; запуск с TTY, но неподходящим TERM — `terminal not cursor addressable`. Рабочий режим: TTY и TERM=xterm-256color. Первая наблюдаемая playback-сессия завершена после 240-секундного лимита ожидания; её поздний resume не засчитан. Последний проход выполнил действия подряд, без пауз на переписку, затем закрыл go2tv (код 0). Discovery ранее завершён клавишей q. Новые файлы/сервера приложения не создавались; native HTTP выдачу обеспечивал go2tv.

**Различие путей управления:** start/file delivery и первая pause — go2tv 2.7.0; последний pause/resume/seek/stop — диагностические HTTP SOAP-запросы AVTransport из Python stdlib, при продолжающейся раздаче go2tv. Это доказывает возможность DLNA-управления данным файлом, но не наличие seek в терминальном UI go2tv. Первый HTTP GET Range с другого LAN-хоста не выполнялся.

**Неудачная попытка SOAP сохранена:** сериализованный ElementTree GetTransportInfo получил HTTP 500 ещё до первой команды управления; даже Stop в той же форме не подтвердился. После закрытия процесса явная форма ниже вернула STOPPED/OK, а новый проход с ней завершился успешно. В первой ошибке тело fault не было сохранено; точный errorCode и причина не установлены. Различие namespace declaration/prefix/serialization — гипотеза для регрессии будущего DLNA-адаптера, не общее утверждение о Sony.

```xml
<s:Envelope xmlns:s="http://schemas.xmlsoap.org/soap/envelope/" s:encodingStyle="http://schemas.xmlsoap.org/soap/encoding/">
  <s:Body><u:GetTransportInfo xmlns:u="urn:schemas-upnp-org:service:AVTransport:1"><InstanceID>0</InstanceID></u:GetTransportInfo></s:Body>
</s:Envelope>
```

Успешные запросы использовали XML declaration UTF-8, Content-Type text/xml; charset="utf-8", SOAPAction в кавычках с service type и action; InstanceID=0. Для Seek: Unit=REL_TIME, Target=00:01:00 и 00:00:15. Для Play: Speed=1. Между действиями 3–4 s; timeout каждого HTTP-запроса 8 s. Контрольные endpoint URI определяются из description, не зашиваются в будущий код.

## Границы вывода

Один совместимый законченный MP4, утилиты на текущей macOS, конкретные устройства. Не проверены приложение/.app Open Media Cast, macOS 14, HLS, remux/transcode, субтитры, другие видео, длительная нагрузка, Cast или Apple TV 4. Результаты поддерживают следующий небольшой direct-play MVP, не объявляют весь v1 готовым.
