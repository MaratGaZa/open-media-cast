# Реализация задачи

Прочитай [AGENTS](../../../AGENTS.md), выбранную строку [плана](../../../docs/plans/IMPLEMENTATION_PLAN.md), связанные требования/ADR и [стратегию проверок](../../../docs/testing/TEST_STRATEGY.md).

Проверь фактический Git root, status, принятие нужного scope и зависимости задачи. Разрешение пользователя на конкретный объём учитывай без повторного запроса. Draft-план сам по себе не разрешает реализацию всех этапов. Начни с issue и новой ветки от актуального `origin/main` по [циклу изменения](../../../docs/runbooks/SDD_AND_AGENTS.md#цикл-изменения--каноническое-правило); не создавай новые remote по предположению.

До изменения контракта обнови требования и criterion, обозначь решение, если оно требуется. Реализуй связный объём задачи, сохрани platform/receiver/domain boundaries и пользовательские изменения. Не создавай новые категории каталогов без согласования структуры.

Выбери проверки по риску изменения. Нельзя завершить hardware acceptance mock-тестом. Для документационной задачи не запускай несуществующий product pipeline. При failure сохрани причину и исправь относящийся к задаче дефект; при внешнем blocker продолжай только независимую разрешённую часть.

Заверши отчётом: REQ IDs, изменения, фактические проверки, snapshot, риски, rollback, незакрытые критерии. `[x]` допустим только при выполненной приёмке. Завершение и действия после вердикта выполняй по каноническому циклу SDD выше; не дублируй его собственным порядком. Release и следующая задача — только по отдельному поручению.
